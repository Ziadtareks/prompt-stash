## Example AI response

**1. VERDICT**
The code returns addresses, but it is not safe to ship as-is: the SQL is injectable, and the endpoint trusts a client-supplied `user_id` with no authentication. Where it breaks first: anyone can read anyone's addresses.

**2. FINDINGS**

| Priority | Issue | Why it matters | Suggested fix |
|---|---|---|---|
| P0 | SQL built with an f-string (`{user_id}` inlined) | Classic injection vector; a `user_id` like `1 OR 1=1` dumps every row | Use a parameterized query: `db.execute("SELECT ... WHERE user_id = :uid", {"uid": user_id})` |
| P0 | No authentication/authorization — `user_id` comes from the query string | Any caller can read any user's addresses by changing the number | Take the user identity from the authenticated session/token, never from client input |
| P1 | `SELECT *` | Exposes new columns by accident later (e.g. soft-delete flags, notes) | Select explicit columns |
| P2 | No pagination or limit | A user with thousands of rows returns them all in one response | Add `LIMIT/OFFSET` or cursor pagination |

**3. SECURITY PASS**
Both classics found: unvalidated/interpolated input (P0 #1) and a missing authz check (P0 #2). No hardcoded credentials in this snippet — but the DB connection settings aren't shown; confirm they come from environment variables, never the source.

**4. THE FIX DIFF** (the auth/SQL core only)

```python
@app.get("/addresses")
def get_addresses(current_user: User = Depends(get_current_user)):
    rows = db.execute(
        "SELECT id, label, line1, city FROM addresses WHERE user_id = :uid",
        {"uid": current_user.id},
    )
    return [dict(r) for r in rows]
```
- `Depends(get_current_user)`: identity now comes from the verified token; the client can no longer name an arbitrary `user_id`.
- Parameterized query kills the injection vector.
- Explicit columns stop accidental data leaks.

**5. THE COMPLIMENT**
The endpoint is small, synchronous-simple, and returns plain dicts — easy to test and reason about. Fix the two P0s and this is a clean little handler.
