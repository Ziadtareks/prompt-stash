# Example — Website Error Fixer

Demonstration of [`prompts/debugging/website-error-fix.txt`](../prompts/debugging/website-error-fix.txt) with the variables filled in. The response below was generated by an AI in one pass and is **an example, not a guaranteed output**. All names and details are fictional.

## Prompt (filled)

> You are a patient senior web developer helping a complete beginner. I will paste an error below. Explain everything in plain, beginner-friendly English — no jargon without a quick explanation.
>
> MY DETAILS
> - What I was doing when it happened: opening my blog after editing a post
> - My stack: WordPress on shared hosting
> - The exact error message: "Error establishing a database connection"
> - Did it ever work before? worked fine yesterday
> - What I already tried: refreshed the page, restarted from the hosting panel
>
> YOUR TASK — answer in this exact order:
> 1. WHAT HAPPENED: restate the error in one sentence a non-coder would understand.
> 2. MOST LIKELY CAUSES: list the 3 most common causes of this exact error, ranked by probability, each with a one-line reason.
> 3. HOW TO CHECK: for each cause, give the fastest safe way to confirm or rule it out (exact clicks, commands, or URLs).
> 4. THE FIX: once the cause is clear, give the smallest safe fix as numbered steps. Warn me before anything destructive.
> 5. VERIFY: how do I confirm it is actually fixed in under a minute?
> 6. PREVENT: one habit or tool that would stop this from coming back.
>
> RULES
> - If critical information is missing, ask up to 3 clarifying questions first; otherwise proceed with clearly-stated assumptions.
> - Never invent file paths or commands for tools I did not mention.
> - If you are missing a key detail, ask me exactly one question before answering.
> - If the fix has any risk (data loss, downtime), say so in one line before the steps.

## Example AI response

**1. WHAT HAPPENED**
Your blog lost its connection to the database — the separate storage area that keeps all your posts and settings — so the site has nothing to show.

**2. MOST LIKELY CAUSES** (ranked for "worked yesterday, broke after edits")
1. **Bad edit to `wp-config.php`** — if you or a plugin changed that file yesterday, one wrong character breaks the database login.
2. **Host-side database issue** — on shared hosting, the database service sometimes crashes or hits a resource limit; usually self-recovers or needs a host restart.
3. **Exceeded hosting plan limits** — a traffic or storage spike can make the host temporarily refuse database connections.

**3. HOW TO CHECK**
- Cause 1: In your hosting panel, open File Manager → the folder containing your site → check if `wp-config.php` was modified in the last 24 hours (look at the "Last Modified" column).
- Cause 2: In the same panel, is there a "Databases" or "MySQL" section showing the database as "up"? Some panels show a red status or an error notice.
- Cause 3: Check your email for a hosting alert ("resource limit reached"), or look at the CPU/usage graph in the panel.

**4. THE FIX**
Most likely fix — restore the config file if it was edited:
1. In File Manager, right-click `wp-config.php` → your host may offer "Restore" from a daily backup (hosting panels usually keep 1–2 days).
2. ⚠️ If no backup exists, don't hand-edit it — copy the file's contents and paste them to me; I'll spot the broken line. **Risk: hand-editing this file wrongly can take the whole site down, not just the database connection.**
If the file wasn't touched: contact your host's support chat and say "my database connection is failing since today — please restart the MySQL service for my account." That's a routine request for them.

**5. VERIFY**
Open your blog in a private/incognito window. If the homepage and one post load, you're fixed (incognito avoids cached pages fooling you).

**6. PREVENT**
Turn on automatic backups (most shared hosts offer daily backups for free or ~1–2 USD/month) — today's fix took 10 minutes because a backup existed or the host could restore; without one it can take hours.
