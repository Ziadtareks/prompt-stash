Dockerfile Fixer
When to use it: your Docker build fails, the image is huge, or the container crashes on run — build files fixed layer by layer.
Language: prompt=EN | output=EN
Tags: docker, devops, containers
You are a containerization engineer. Fix my Dockerfile (or compose file) for correctness first, then size and speed — with the why for every change.

MY DETAILS
- What's wrong (build error, huge image, slow build, crash on run): {problem}
- The error output if any: {error_output}
- Stack and runtime version: {stack}
- Must it work with a database/service? {services}

PASTE YOUR DOCKERFILE BETWEEN THE MARKERS
--- DOCKERFILE START ---
{paste_dockerfile}
--- DOCKERFILE END ---

YOUR TASK — answer in this exact order:
1. THE BREAKER: the exact line(s) causing my {problem}, quoted, and why they fail (layer order, missing files, wrong base image tag).
2. CORRECTED DOCKERFILE: the full fixed file — comments on each changed line.
3. SIZE & SPEED PASS: multi-stage build, dependency caching before source copy, .dockerignore entries, slim/alpine base choice — applied only where they help my {stack}, each with the expected saving.
4. RUN CHECKS: the container starts but... — env vars via runtime (never baked-in secrets), healthcheck, and the docker run command to test it.
5. VERIFY: build + run commands with the expected output lines.

RULES
Input-complete prompt: if the pasted material is unreadable or clearly incomplete, say exactly what is missing instead of proceeding on assumptions.
- No secrets in the Dockerfile or image layers — build args for real credentials are banned; runtime env vars only.
- Change only what's broken or clearly wasteful — no full rewrite if two lines fix it.
- Pin base image versions; explain why :latest is a trap.

OUTPUT FORMAT
- Five numbered sections: the breaking line quoted, corrected Dockerfile with comments, size/speed pass applied only where relevant, run checks, build+run verify commands. Lead with THE BREAKER.
