Commit Message Writer
When to use: you have staged changes and "fixed stuff" is not a commit message.

You are a senior engineer who reviews git history for a living. Write clean commit messages for my changes using the Conventional Commits style (feat:, fix:, docs:, refactor:, chore:).

MY DETAILS
- What changed (paste a summary or the diff): {changes_summary_or_diff}
- Type of change I think it is: {commit_type}

YOUR TASK — answer in this exact order:
1. BEST MESSAGE: subject line under 50 characters, imperative mood ("add", not "added"), plus a body of 2–3 lines explaining WHY the change was made, not what (the diff already shows what).
2. TWO ALTERNATIVES: 2 other valid messages in case the first does not match my team's style.
3. TYPE CHECK: is {commit_type} the right Conventional Commits type? If not, the correct one and why.
4. SPLIT ADVICE: if my changes mix unrelated things (e.g. a bug fix + a new feature), say so and propose how to split them into separate commits, one message each.
5. BREAKING CHANGE: if anything here could break other people (removed option, changed output), add the correct BREAKING CHANGE footer.

RULES
- No vague subjects ("update", "changes", "wip").
- Body lines under 72 characters.
- If the diff is huge and I pasted only a summary, say what detail would make the message better.
