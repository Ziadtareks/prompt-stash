SQL Query Fixer
When to use it: your SQL query returns wrong rows, or it is slow and you do not know why.
Language: prompt=EN | output=EN
Tags: sql, databases, debugging
You are a database engineer who fixes queries all day. Diagnose my query, fix it, and prove the fix — without touching anything outside the query unless it is truly needed.

MY DETAILS
- My query: {sql_query}
- What is wrong (wrong results, too slow, error message): {what_is_wrong}
- Table schemas (columns, types, indexes if known): {table_schemas}

YOUR TASK — answer in this exact order:
1. DIAGNOSIS: is this a correctness problem, a performance problem, or both? One line each.
2. THE BUG IN PLAIN WORDS: what my query actually does vs what I want, in beginner language (e.g. "your WHERE filters after the join, so rows disappear").
3. THE FIXED QUERY: corrected SQL with a one-line comment on each changed part.
4. WHY IT WORKS: 2–3 sentences on the logic of the fix.
5. PERFORMANCE: if slow — the index that would help most (exact CREATE INDEX statement) and the expected effect; if already fast, say skip.
6. VERIFY: how to prove the fix (compare row counts, run EXPLAIN, check a known case) in concrete steps.

RULES
If the goal is ambiguous (e.g. which rows are 'wrong'), ask exactly one question; otherwise proceed with stated assumptions.
- Keep my table and column names exactly as given.
- Prefer the smallest change over a rewrite.
- If my goal is ambiguous, ask one question before fixing.

OUTPUT FORMAT
- Six numbered sections: diagnosis (1 line), bug in plain words (≤3 sentences), fixed SQL with per-change comments, why it works (≤3 sentences), index suggestion or 'skip', verify steps. Lead with DIAGNOSIS.

# Variables
- {sql_query}: Your current SQL query.
- {what_is_wrong}: The what is wrong for this prompt — see Example values for a realistic fill.
- {table_schemas}: Your tables and columns.

# Example values: {sql_query}=SELECT * FROM orders WHERE customer_id IN (SELECT id FROM customers WHERE city = 'Cairo') AND total > 1000 | {what_is_wrong}=returns orders twice for some customers | {table_schemas}=orders(id, customer_id, total, status), customers(id, name, city)
