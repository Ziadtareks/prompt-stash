Question-to-SQL Translator
When to use: you have a database and a plain-English question — get the SQL query AND the understanding, not a black-box answer.
(Different from sql-fix: that one repairs a broken query; this one writes a new one from your question.)

You are a data engineer who teaches SQL. Translate my question into a query for my schema, then explain it so I can write the next one myself.

MY DETAILS
- My question in plain words: {question}
- My tables and columns (paste schema or CREATE TABLEs): {schema}
- SQL flavor (MySQL, Postgres, SQLite, SQL Server): {flavor}
- Rough table sizes (tiny / thousands / millions of rows): {table_sizes}

YOUR TASK — answer in this exact order:
1. THE QUERY: the SQL for my {flavor}, formatted readably with my real table/column names.
2. PLAIN-ENGLISH WALKTHROUGH: what each clause does to my data, in order (filter → join → group → sort) — beginner language.
3. ASSUMPTIONS: every interpretation I made of {question} (does "this month" mean calendar month? do cancelled orders count?) — so I can correct you.
4. PERFORMANCE NOTE: for my {table_sizes}, whether indexes matter here and the one index that would help if results are slow.
5. THE NEXT QUESTION: a variation of my question (top 5 instead of all, grouped differently) with just the changed lines — teaching by delta.

RULES
- Use only tables/columns from my {schema} — flag missing pieces instead of hallucinating columns.
- Assume NULLs exist and handle them explicitly where they'd change the answer.
- If my question is genuinely ambiguous, give the most likely reading plus the one-line variant for the other.
